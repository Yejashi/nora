## Acceptance criteria

### 1. Real apps on native Wayland and X11

- **Native Wayland (node 0):** L1 smoke exit 0 (RADV Vulkan adapter, `smoke: presented 1 frame`, resize + minimize exercised); L2 idle pulse = exactly one frame rendered then coalesced pulses, exit 0; L3 WINSIZE — the child's `stty size` output (`25 66`) is visible in the rendered grid, exit 0; L4 child-exit close — no drain/timeout warning, prompt close in ~1.5 s; L5 `--hold` — exit 124 at 15 s with `child exit status Some(3)` + `hold active`, control leg exit 3.
- **Native X11:** unverified on this cluster — both nodes are Wayland-only (node 0: `:0` is XWayland, no Xorg; node 1: rootless Xwayland `:0`, no Xorg, `loginctl` session `Type=wayland`). The X11 code path is implemented (winit `x11` feature) and headless-tested, but no native X11 session was available to exercise it live.
- **Apps:** node 0 legs ran real child processes (`nora_child`, `/bin/sh`) inside windows. The real-app matrix ran on node 1 (native Wayland, `timeout 20 nora -- <app>`; all 5 apps installed): bash/vim/htop/tmux → exit 124 (hosted, still running at 20 s); less → exit 0 (hosted, exited cleanly, frame rendered, `child exit status Some(0)`). No panics, no non-zero non-124 exits. SSH: skipped — no remote prerequisite configured on this cluster.

6. **Kitty graphics:** not in v0.1 (N32–N36; ADR-011).

## Release decision

**v0.1 acceptance met on native Wayland; native X11 live evidence is a documented limitation.**

- Every v0.1 requirement that can be exercised on this cluster passes: the final full gate is 455/0 on the acceptance tree (`522bd07`); the native-Wayland live matrix (L1–L5) passes on node 0 (RADV) and the real-app matrix (bash/less/vim/htop/tmux) passes on node 1 (RADV); P01–P10 all complete `ok: true`; resource limits 11/11; clean install and repeated lifecycle stress green (N31a).
- **The single unmet item is environmental, not a code defect:** criterion 1's native-X11 live half could not be exercised because neither node on this cluster runs a native X11 session (both are Wayland-only; `:0` is XWayland on both, no Xorg). The X11 code path is implemented (winit `x11` feature) and headless-tested, so the gap is live evidence, not a known bug.
- **Verdict:** release is **not blocked by the implementation**. v0.1 is accepted for native Wayland. Native-X11 live verification should be re-run on a host with a real Xorg session before a final sign-off; until then it stands as the one documented, environment-limited gap.
